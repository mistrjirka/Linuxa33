## Observed result

`pmbootstrap install` completed successfully and `pmbootstrap export` advertised:

- `samsung-a33x.img`
- `samsung-a33x-root.img`
- `samsung-a33x-boot.img`

The split root link resolved to:

```text
/home/jirka/.local/var/pmbootstrap/chroot_native/home/pmos/rootfs/samsung-a33x-root.img
```

but that file was not materialized. The preparation script therefore stopped before creating durable artifacts:

```text
REFUSING: pmbootstrap export did not produce root-image
```

This was a host-export representation problem, not a rootfs build failure and not a phone failure. The combined disk image was generated by the successful `pmbootstrap install` run. No phone access, flash, format, mount or partition write occurred.

## Corrected strategy

Commit `992a752fef797b0915dc11016177ed9aedb37f64` changes `scripts/prepare-a33-standalone-rootfs-image.sh` to treat `samsung-a33x.img` as the authoritative pmbootstrap output.

The script now:

1. reuses the already generated combined image unless `FORCE_REBUILD=1` or the image is absent;
2. parses the combined image partition table with `sfdisk --json`;
3. requires exactly two valid partitions;
4. identifies the larger partition as root and the smaller partition as boot;
5. uses exported split images when they genuinely exist;
6. otherwise extracts exact sector ranges with `dd` using the partition geometry;
7. validates extracted byte counts;
8. requires an ext4 root filesystem;
9. runs read-only `e2fsck`;
10. verifies `/sbin/init`, OpenSSH, enabled OpenRC links, NetworkManager and the U0g helper/hooks inside the image;
11. calculates filesystem used space and minimum shrinkable size;
12. stores durable artifacts below `~/a33-port/build/rootfs-images/`.

This avoids recreating the filesystem from a directory and therefore preserves the exact filesystem generated by pmbootstrap.
