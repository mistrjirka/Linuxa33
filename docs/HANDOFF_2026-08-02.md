# Samsung Galaxy A33 5G postmarketOS port — cold-start handoff

Date: 2026-08-02

## 1. Goal

Create a real postmarketOS port for the Samsung Galaxy A33 5G, not an A53 image adapted at flash time. The immediate milestone is a reliable Linux console/debug boot from recovery with USB networking. Later milestones are installing a persistent root filesystem and enabling hardware incrementally.

The archived Samsung A53 package is a template only because the A33 and A53 use Exynos 1280 / `s5e8825`. **Never flash an A53 image to the A33.**

## 3. Bootloader and firmware history

An early experiment with a homemade empty vbmeta failed with:

```text
SW REV CHECK FAIL (VBMETA) DEVICE: 0xD BINARY: 0x0
```

The exact stock firmware was then restored successfully with Odin4.

Magisk 30.7 was installed by the standard Samsung patched-AP workflow. The patched AP changed boot and vbmeta while leaving recovery, vendor_boot, DTBO and vbmeta_system unchanged. Android booted successfully afterward. A small Magisk module was used to permit ADB shell UID 2000 to obtain root.

Do not repeat the homemade vbmeta experiment.

## 7. A33 package work completed

Two local packages were created under `device/downstream`:

```text
device-samsung-a33x
linux-samsung-a33x
```

The kernel package uses prebuilt files from the proven TWRP recovery:

```text
Image
samsung-a33x.dtb
recovery_dtbo
modules.tar.gz
```

Kernel release exported to postmarketOS:

```text
5.10.66-Gabriel260BR-TWRP-ga0103aac9499
```

The current module metadata solution uses a package trigger that executes `depmod -a` after installation. Earlier attempts failed because:

1. modules were initially placed under `/lib/modules` while current postmarketOS `mkinitfs` searched `/usr/lib/modules`;
2. `modules.dep` was absent;
3. a post-install script generated files that did not survive the APK transaction as expected;
4. pre-generated indexes from `modules.tar.gz` were not retained in the resulting package due to the packaging/trigger behavior.

The final tested state generated `modules.dep` and allowed `mkinitfs` to complete successfully.

The device package includes a generated `modules-initfs` list derived from every entry in TWRP's `modules.load.recovery`. The final initramfs contains 315 `.ko` modules.

## 12. Immediate recovery procedure

First attempt normal Android boot rather than repeatedly entering recovery.

When Android and Magisk root are available, restore official TWRP:

```bash
adb push reference/twrp/recovery.img /data/local/tmp/twrp-recovery.img
adb shell 'su -c "dd if=/data/local/tmp/twrp-recovery.img of=/dev/block/by-name/recovery bs=4M && sync"'
adb reboot recovery
```

After restoring, verify the recovery partition hash:

```bash
adb shell 'sha256sum /dev/block/by-name/recovery'
```

Expected:

```text
414df197c21de25fc5627cd3a4d8a59011bef0141cfa479560c48aa378d3ad7e
```

If Android cannot be reached, restore the official TWRP image with the same Odin4/download-mode procedure previously proven on this device.

## 13. Highest-priority diagnostics after restoration

Do not immediately build another random recovery image. Capture the reason for the reset.

### 13.1 Pull persistent kernel logs

After one failed postmarketOS boot, boot TWRP or Android and inspect:

```bash
adb shell 'ls -la /sys/fs/pstore 2>/dev/null'
adb pull /sys/fs/pstore logs/pstore
adb shell 'cat /proc/last_kmsg 2>/dev/null' > logs/last_kmsg.txt
```

Also inspect Samsung debug/ramoops facilities exposed by this kernel and any recovery logs. Remove serial numbers and other personal identifiers before committing logs.

### 13.2 Determine the reset interval

Record whether the reset happens immediately, after several seconds, or after approximately a watchdog timeout. This distinguishes bootloader rejection, kernel panic and userspace/watchdog failure.

### 13.3 Test bootloader acceptance separately

A structurally valid image can still be rejected before the kernel starts. A useful controlled test is to rebuild TWRP unchanged but sign its AVB footer with the same local test key. If that image bootloops, the local AVB key is not accepted in this path. If it boots, the failure is in the postmarketOS ramdisk/userspace.

Do not change vbmeta for this test.

### 13.4 Treat missing `CONFIG_DEVTMPFS` as a serious issue

The current kernel reports no `CONFIG_DEVTMPFS` or `CONFIG_DEVTMPFS_MOUNT`. The TWRP ramdisk may provide a pre-populated static `/dev`, while postmarketOS `mkinitfs` normally expects kernel-managed device nodes/udev behavior. This is a leading hypothesis for failure after kernel start.

Two robust paths:

1. build the TWRP/A33 kernel source with the required postmarketOS/OpenRC options enabled; or
2. create a hybrid first-stage ramdisk based on the proven TWRP ramdisk, retaining its `/dev`, init/module-loading and USB setup, then launch a minimal Linux shell or pivot/chroot into postmarketOS.

The second path is likely the fastest way to prove postmarketOS userspace on the phone without first solving every kernel configuration issue.

### 13.5 Add visible and persistent diagnostics

For the next image, consider:

- `verbose-initfs` hook;
- `maximum-attention` hook;
- writing progress markers to pstore or a small writable partition;
- disabling or extending the Samsung soft watchdog during debugging;
- preserving TWRP USB gadget initialization rather than relying solely on postmarketOS NCM;
- adding a minimal emergency `init` that never reboots and logs each stage.

## 14. Suggested next engineering direction

The cleanest long-term port should stop relying on a prebuilt recovery kernel. Locate and build the exact A33/TWRP kernel source and defconfig, then enable at least the kernel features required by postmarketOS/OpenRC and its initramfs. Preserve the proven A33 DTB, recovery-DTBO and module behavior while changing as little as possible per experiment.

A good staged plan:

1. Restore exact TWRP.
2. Capture pstore/last-kmsg after the failed boot.
3. Test an unchanged TWRP ramdisk rebuilt and signed with the local key.
4. Test a TWRP-derived ramdisk with only a trivial persistent shell/progress marker.
5. Test TWRP first-stage plus postmarketOS userspace.
6. Build a corrected A33 kernel with `DEVTMPFS` and other required options.
7. Only after reliable initramfs boot, install the postmarketOS root image to dedicated storage/userdata.
